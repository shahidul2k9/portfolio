Software Engineering Research

Software EvolutionSoftware TestingTechnical DebtPublications

Software maintenance costs often exceed initial development costs. My research at the University of Manitoba focused on reducing this burden through software evolution, software testing, and technical debt.

Software Evolution

Accurate method histories help developers understand past changes, investigate defects, and maintain software with confidence. I proposed and implemented HistoryFinder, an algorithm that reconstructs how individual Java methods change over time. I evaluated HistoryFinder against existing tools and found that it improved accuracy and completeness while remaining competitive in runtime. I presented this work at ICSE 2026, a leading international software engineering conference.

Software Testing

As software changes, developers must keep its tests useful and maintainable. Line-level analysis can lose the context of the surrounding test, while file-level analysis is too coarse to distinguish individual tests. Method-level analysis provides the appropriate granularity for understanding how tests evolve. I investigated the evolution of individual test methods across software histories to provide a more detailed view of how test code develops over time. I found that test code often evolves independently of production code, with frequent changes to small tests associated with more test smells. This manuscript is under review at MSR 2027.

Technical Debt

Technical debt is the future maintenance work created by shortcuts or unresolved design problems in software. I analyzed comments in test code to classify the debt developers acknowledged and found that it has test-specific characteristics that existing tools—and even LLMs—do not detect reliably. This work was published in the Journal of Systems and Software (JSS, 2026).

Method-level test code evolution

Test code needs maintenance just as production code does. I investigated how individual test methods evolve and found that their changes often occur independently of the production code they exercise. Under review at the International Conference on Mining Software Repositories (MSR, 2027).

A First Look at the Self-Admitted Technical Debt in Test Code: Taxonomy and Detection

Technical debt in tests can increase maintenance effort and make future changes harder. I manually identified and classified self-admitted technical debt in test-code comments, then evaluated existing detection tools and LLMs. The results showed that neither approach reliably detects this debt, highlighting the need for methods tailored to test code. Published in the Journal of Systems and Software (JSS, 2026).
